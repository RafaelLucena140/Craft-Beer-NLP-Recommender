# V3: qualidade dos dados e recomendacao

## O que mudou

- `clean_data` agrupa as avaliacoes por identificador da cerveja antes de amostrar o catalogo. As notas sao medias, o ABV e a mediana, `review_count` conta avaliacoes validas e `review_overall_std` mostra a dispersao da nota geral.
- Campos ausentes continuam desconhecidos. O texto sintetico enviado ao embedding os identifica como desconhecidos; os metadados numericos guardam indicadores `*_known` para diferenciar ausencia de uma nota zero.
- O app Streamlit e o chat CLI usam o mesmo modulo `recommender.py` para recuperar, filtrar, reordenar candidatos e gerar respostas fundamentadas nos dados recuperados.
- Filtros estruturados incluem estilos do catalogo, limites de ABV e notas altas com um minimo configuravel de avaliacoes. Criterios nao interpretados como filtro continuam na busca semantica. A interface mostra os filtros detectados e os dados das cervejas recuperadas.
- O reranking combina distancia semantica, nota geral suavizada em direcao a media do catalogo e volume de avaliacoes. Assim, uma nota alta com poucas avaliacoes tem menos peso.
- O Chroma usa a imagem `chromadb/chroma:1.0.0` e publica a porta apenas em `127.0.0.1`. A configuracao do app e dos scripts esta centralizada em `settings.py`.
- A action Python Quality executa Ruff em pushes e pull requests.

## Executar localmente

Requisitos: Python 3.11+, Docker Desktop e Ollama. O CSV fonte nao e distribuido no Git e deve estar em `data/raw/beers_dataset.csv`.

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
ollama pull llama3.2
docker compose up -d
python -m data_pipeline.clean_data
python -m data_pipeline.ingest_vectors
streamlit run app.py
```

Para gerar o relatorio offline:

```powershell
python -m data_pipeline.evaluate_retrieval --cases evaluation/retrieval_cases.json --output evaluation/retrieval_report.json -k 5
```

## Configuracao

Defina as variaveis de ambiente antes de iniciar os processos. Por exemplo, no PowerShell:

```powershell
$env:BEER_SAMPLE_SIZE = "5000"
$env:BEER_SAMPLE_SEED = "42"
$env:CHROMA_HOST = "localhost"
$env:CHROMA_PORT = "8000"
$env:CHROMA_COLLECTION = "craft_beers"
$env:EMBEDDING_MODEL = "all-MiniLM-L6-v2"
$env:OLLAMA_BASE_URL = "http://127.0.0.1:11434"
$env:OLLAMA_MODEL = "llama3.2"
$env:RETRIEVAL_K = "5"
$env:RETRIEVAL_CANDIDATES = "30"
$env:MINIMUM_RATING_REVIEWS = "5"
$env:HIGH_RATING_THRESHOLD = "4.0"
```

Tambem estao disponiveis `BEER_RAW_DATA_PATH`, `BEER_DATA_PATH` e `INGESTION_BATCH_SIZE`.

## Limites da avaliacao

O conjunto atual usa estilos como rotulos proxy. O avaliador nao aplica filtros baseados nesses rotulos; ele consulta por similaridade, aplica o mesmo reranking da aplicacao e mede os resultados contra as classes-alvo. Isso evita que o alvo da avaliacao force diretamente a resposta. Para uma medida de relevancia semantica mais forte, adicione cervejas relevantes por consulta revisadas por avaliadores humanos.
